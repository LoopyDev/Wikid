# AI Block Summary Cache

Reduces the token cost of AI "Suggest edits" calls by 60–85% on large pages. Instead of sending every block as full text on every request, non-target blocks are replaced with one-sentence semantic summaries generated by `claude-haiku-4-5-20251001`.

## Problem

The AI edit flow (`POST /ai/suggest`) previously sent the entire page to `claude-sonnet-4-6` on every call. A 50-block page sends ~7,500 tokens even when the user is editing a single section.

## How It Works

### 1. On-Request Summarization

Summarization runs **as the first step of every "Suggest edits" request** — not in the background. When the user submits an edit instruction:

1. `summarizeForAi()` is called before the main AI request.
2. It scans all top-level blocks for those with no cached summary and sends them in batches of 10 to `POST /ai/summarize-blocks`.
3. The stats bar in the panel shows progress: "Indexing context… (X / Y blocks)".
4. Once all batches complete, the actual `POST /ai/suggest` call fires.

This means summarization always runs on settled content (whatever is in the doc when the user submits), with no wasted API calls during active writing.

The `onUpdate` handler in `useBlockSummarizer` still runs on every edit, but **only to recompute the stats display** — it makes no API calls.

A block is only summarized if:
- It is a summarizable type (`paragraph`, `heading`, `blockquote`, `codeBlock`)
- Its text is ≥50 chars (`isShort` threshold)
- It has no existing cache entry (keyed by content hash)

A block is re-summarized only if its text changes (new hash).

### 2. Section Detection

`serializeBlocksForAi()` identifies the **target section**: the heading-bounded region where the cursor was last active.

- Walk upward from the cursor to find the nearest `heading` — this is the section start.
- Walk downward to find the next heading at the same or higher level — this is the section end.
- If no headings exist, use a 15-block window centred on the cursor.
- If the page has ≤15 serializable blocks, the entire page is treated as the target (no summarization needed).

`lastKnownCursorPos` is captured in both `onSelectionUpdate` and `onBlur`, preserving the correct position even after the user clicks into the AI panel.

### 3. Payload Composition

`serializeBlocksForAi()` builds the block array sent to the backend:

- **Target section blocks** → `{ index, type, text }` — inline markdown (bold, italic, code, links preserved)
- **All other blocks** → `{ index, type, text: "[CONTEXT: <summary>]" }` — cached summary, or an extractive fallback (first 80 chars) if no summary exists yet

The system prompt instructs the model never to include `[CONTEXT: ...]` blocks in its `changes` array — they are read-only structural context.

### 4. Markdown Round-Trip

Target-section blocks are serialized using `nodeToInlineMarkdown()` (not `node.textContent`), which preserves inline formatting:

- `**bold**`, `*italic*`, `***bold italic***`
- `` `inline code` ``
- `~~strikethrough~~`
- `[link text](url)`
- Marks with no markdown equivalent (`highlight`, `textStyle`) pass through as plain text

The AI is instructed to return `newText` using the same inline markdown syntax. On apply, `markdownToInlineFragment()` parses the response back into a ProseMirror Fragment using `DOMParser.fromSchema(schema)` — the editor's own schema rules are used, so custom marks are handled correctly.

On revert, `tr.replaceWith(from, to, originalNode)` restores the exact original ProseMirror node including all marks — no information loss.

See [`ai-markdown.md`](./ai-markdown.md) for full details on the markdown utilities.

## API

### `POST /ai/summarize-blocks`

**Request:**
```json
{ "blocks": [{ "index": 2, "type": "paragraph", "text": "Full block text..." }] }
```

**Response:**
```json
[{ "index": 2, "summary": "Describes the authentication flow for API clients." }]
```

Uses `claude-haiku-4-5-20251001`. Max 1,024 output tokens per batch of 10 blocks.

### `POST /ai/suggest`

**Request blocks field** (after summarization):
```json
[
  { "index": 0, "type": "heading",   "text": "**Introduction**" },
  { "index": 1, "type": "paragraph", "text": "[CONTEXT: Overview of deployment steps.]" },
  { "index": 2, "type": "paragraph", "text": "The service *must* be restarted after config changes." }
]
```

**Response `newText`** uses inline markdown:
```json
{ "changes": [{ "index": 2, "newText": "The service **must** be restarted after any configuration changes." }] }
```

## Cache

Stored in `localStorage` at key `wikid:block-summary-cache`.

```json
{
  "a3f1b2c4": { "summary": "Explains the deployment steps for Docker Compose.", "ts": 1709123456 }
}
```

- Key: FNV-1a 32-bit hash of the block's plain text content (hex string)
- Eviction: oldest entries removed when count exceeds 2,000
- Invalidation: automatic — a changed block produces a new hash

## Expected Token Savings

| Page | All full text | After warm cache | Reduction |
|---|---|---|---|
| 50 blocks, 20-block section | ~7,500 tokens | ~3,450 tokens | ~54% |
| 100 blocks, 25-block section | ~15,000 tokens | ~4,875 tokens | ~67% |

Haiku summarization cost is ~$0.002 for a full 50-block page, amortised across all subsequent edit requests for unchanged content.

## Edge Cases

| Scenario | Behaviour |
|---|---|
| Page ≤15 serializable blocks | All blocks sent as full text; no summarization |
| No headings in document | 15-block window centred on cursor |
| Cursor not in editor | `onBlur` preserved last position before focus moved to AI panel |
| Uncached block at request time | Extractive fallback (first 80 chars + `…`) used; request proceeds immediately |
| Summarization API error | Silently swallowed; fallback used; cache not updated |
| Block deleted | Not included in `doc.forEach` iteration; its cache entry persists but is never accessed unless the same text reappears |
| Block edited after AI accept | New hash → re-summarized on next request |
| Page switch | TiptapEditor remounts with fresh composable; cache persists in localStorage across pages |
| User submits before summarization finishes | Cannot happen — `sendEditSuggestion` awaits `summarizeForAi()` before calling the AI |
